# راهنمای آزمون‌های Unique Pro

این پوشه شامل آزمون‌های رگرسیون برنامهٔ واقعی و ابزارهای کمکی آن است. آزمون‌ها با دادهٔ ساختگی اجرا می‌شوند؛ از اطلاعات مشتری یا نسخهٔ پشتیبان واقعی در تست استفاده نکنید.

## فایل‌ها

| فایل | مسئولیت |
|---|---|
| `run_tests.py` | اجرای مجموعهٔ آزمون مرورگری روی برنامه در Chromium |
| `helpers.js` | ابزارهای تزریق‌شده به صفحه و ساخت دادهٔ آزمایشی |
| `headless_probe.js` | بررسی پایهٔ اجرای موتور در Node.js |

## حوزه‌های پوشش

- خرید، فروش، مالیات، پرداخت ترکیبی، برگشت و ابطال
- FIFO و میانگین موزون، موجودی، انتقال و انبارگردانی
- صندوق، چک، وام و توازن اسناد حسابداری
- نقش‌ها، سطح دسترسی و PIN
- IndexedDB، مهاجرت داده، رمزگذاری و پشتیبان‌گیری
- QR و گزارش‌های مدیریتی
- دستیار هوشمند و کنترل عملیات نیازمند تأیید
- بارگذاری OCR فارسی/انگلیسی و استفاده از بستهٔ OCR بدون اینترنت

پوشش آزمون به‌معنای تضمین همهٔ ترکیب‌های ممکن یا تأیید کارکرد روی تمام دستگاه‌ها نیست. آزمون واقعی دوربین، میکروفون و گوشی Android باید جداگانه انجام شود.

## پیش‌نیازها

Python 3، Node.js و Chromium موردنیاز Playwright:

```bash
python -m pip install playwright numpy opencv-python-headless
python -m playwright install chromium
```

## اجرای محلی

ابتدا از ریشهٔ مخزن سرور را اجرا کنید:

```bash
python -m http.server 8765
```

در ترمینال دوم، از ریشهٔ مخزن:

```bash
python tests/run_tests.py
```

برای اجرای آزمون‌هایی که نامشان با عبارت مشخصی تطبیق دارد:

```bash
python tests/run_tests.py "عبارت جست‌وجو"
```

## اجرای خودکار

گردش‌کار `.github/workflows/regression-tests.yml` روی push به `main`، درخواست Pull Request به `main` و اجرای دستی فعال می‌شود. این workflow توزیع استاتیک را در محیط موقت CI می‌سازد و آزمون مرورگری را روی همان خروجی اجرا می‌کند؛ فایل‌های خروجی build نباید به‌عنوان منبع اصلی کد commit شوند.

برای گزارش نتیجه، لینک اجرای GitHub Actions و SHA دقیق commit را ذکر کنید. تعداد آزمون‌ها و Assertionها را از خروجی همان اجرا بردارید؛ اعداد اجرای قدیمی را به‌عنوان وضعیت فعلی تکرار نکنید.

## نکات

- آزمون QR از OpenCV استفاده می‌کند؛ اگر وابستگی نصب نباشد، بررسی مربوط ممکن است SKIP شود.
- شکست آزمون را با حذف assertion یا تبدیل آن به SKIP پنهان نکنید.
- پس از تغییر منطق مالی، مسیر موفق و مسیر شکست/rollback را هر دو پوشش دهید.
- برای جزئیات وضعیت جاری و ریسک‌های آزمون میدانی به [گزارش وضعیت پروژه](../PROJECT_STATUS.md) مراجعه کنید.
