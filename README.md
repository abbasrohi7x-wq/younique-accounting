# Unique Pro — یونیک

**نرم‌افزار مدیریت فروشگاه، خریدوفروش، انبار و حسابداری**  
نسخهٔ کاری: **Unique Pro 1.0** · زبان رابط: فارسی · جهت: RTL · معماری: وب‌اپ آفلاین‌محور (PWA)

Unique Pro برای مدیریت گردش روزانهٔ فروشگاه طراحی شده است. کدبیس فعلی به‌صورت تدریجی ارتقا پیدا می‌کند؛ هدف، حفظ ساختار موجود و اصلاح امن آن است، نه بازنویسی موازی یا ایجاد نسخهٔ دوم.

## وضعیت انتشار

- مخزن کد: [abbasrohi7x-wq/younique-accounting](https://github.com/abbasrohi7x-wq/younique-accounting)
- میزبان هدف: GitHub Pages
- نشانی مورد انتظار: [abbasrohi7x-wq.github.io/younique-accounting](https://abbasrohi7x-wq.github.io/younique-accounting/)
- وضعیت انتشار و اجرای زنده باید از صفحهٔ Actions و بررسی مستقیم سایت تأیید شود؛ وجود تنظیم Pages به‌تنهایی اثبات سلامت انتشار نیست.
- Vercel مسیر انتشار هدف فعلی نیست و تنظیمات قبلی آن تا تأیید کامل Pages حفظ می‌شود.

## قابلیت‌ها و محدودهٔ پروژه

کدبیس شامل بخش‌هایی برای فروش، خرید، کالا و تنوع کالا، انبار و انتقال، صندوق و پرداخت، حسابداری و گزارش‌ها، پشتیبان‌گیری، دستیار فارسی و OCR محلی است. وجود کد هر بخش به‌معنای تأیید نهایی همهٔ سناریوهای آن نیست؛ وضعیت اعتبارسنجی در [گزارش وضعیت پروژه](PROJECT_STATUS.md) ثبت می‌شود.

گردش اصلی کسب‌وکار:
1. تعریف کالا و مشخصات/تنوع آن.
2. ثبت فاکتور خرید و ورود موجودی به انبار.
3. ثبت فروش از موجودی قابل‌فروش.
4. تخصیص مبلغ فاکتور به یک یا چند روش پرداخت و کنترل توازن مالی.
5. نگهداری سابقهٔ اسناد، برگشت‌ها و گزارش‌ها.

## اجرا

این پروژه در ساختار فعلی به مرحلهٔ build اجباری نیاز ندارد. در ریشهٔ مخزن:

```bash
python3 -m http.server 8080
```

سپس `http://localhost:8080` را باز کنید. برای PWA، Service Worker، دوربین و OCR از `file://` استفاده نکنید؛ برنامه باید از مبدأ HTTP/HTTPS اجرا شود.

## انتشار با GitHub Pages

1. در مخزن، **Settings → Pages** را باز کنید.
2. روش انتشار را روی **Deploy from a branch** قرار دهید.
3. شاخهٔ `main` و پوشهٔ `/(root)` را انتخاب کنید.
4. پس از انتشار، صفحهٔ Actions و نشانی عمومی برنامه را بررسی کنید.
5. در مرورگر، manifest، ثبت Service Worker، بارگذاری منابع در مسیر زیرشاخه‌ای و اجرای مجدد پس از قطع اینترنت را آزمایش کنید.

GitHub Pages میزبان فایل‌های استاتیک است؛ API، پایگاه دادهٔ ابری یا همگام‌سازی خودکار چنددستگاهی فراهم نمی‌کند.

## آزمون و کنترل کیفیت

نیازمندی‌ها:

```bash
python -m pip install playwright numpy opencv-python-headless
python -m playwright install chromium
```

سرور را در یک ترمینال اجرا کنید و در ترمینال دیگر:

```bash
python3 tests/run_tests.py
```

یا یک آزمون مشخص:

```bash
python3 tests/run_tests.py نام_آزمون
```

GitHub Actions همین مجموعه را برای push به `main` و Pull Request اجرا می‌کند. فقط نتیجهٔ سبز همان commit، مدرک موفقیت آن commit است. گزارش‌های قدیمی در [CHANGES_FA.md](CHANGES_FA.md) تاریخچه‌اند، نه وضعیت زنده.

## داده و حریم خصوصی

- داده‌های عملیاتی برنامه روی دستگاه کاربر نگهداری می‌شوند؛ قبل از پاک‌کردن دادهٔ مرورگر یا تعویض دستگاه، از مسیر پشتیبان‌گیری برنامه استفاده کنید.
- انتقال داده بین دستگاه‌ها با فایل پشتیبان و اقدام صریح کاربر انجام می‌شود؛ GitHub Pages این داده‌ها را بین دستگاه‌ها همگام نمی‌کند.
- کلید API، رمز، token، فایل پشتیبان واقعی یا دادهٔ مشتری را در مخزن commit نکنید.
- برای OCR محلی، فایل‌های موتور و داده‌های زبان در `vendor/tesseract/` نگهداری می‌شوند؛ مجوزها و اثرانگشت فایل‌ها در همان پوشه قرار دارند.

## نقشهٔ مخزن

| مسیر | کاربرد |
|---|---|
| `index.html` | برنامهٔ اصلی و رابط اجرایی |
| `manifest.json` | تنظیمات نصب PWA |
| `service-worker.js` | کش، آفلاین و به‌روزرسانی |
| `src/engine/` | اجزای استخراج‌شدهٔ موتور مالی |
| `src/ui/` | منطق کمکی رابط و دستیار |
| `tests/` | آزمون‌های رگرسیون و ابزارهای تست |
| `vendor/` | منابع محلی شخص ثالث و فونت‌ها |
| `.github/workflows/` | گردش‌کارهای CI |
| `docs/` | مستندات فنی و تصمیم‌های مهندسی |
