# Unique Pro 1.0 — یونیک

سامانهٔ فارسی و راست‌چین مدیریت فروشگاه کفش و کتانی، خرید، فروش، انبار، صندوق و حسابداری. هستهٔ عملیاتی برنامه به‌صورت local-first طراحی شده و برای ثبت فروش و خرید به API یا پایگاه دادهٔ ابری نیاز ندارد.

## اجرای محلی

برای فعال بودن IndexedDB، Service Worker، OCR و میکروفون، برنامه را از `http://localhost` یا `https://` اجرا کنید؛ اجرای مستقیم فایل با `file://` پشتیبانی نمی‌شود.

```bash
python3 -m http.server 8080
```

سپس `http://localhost:8080` را باز کنید.

## انتشار با GitHub Pages

انتشار فقط از طریق GitHub Pages و workflow یگانهٔ `.github/workflows/static.yml` انجام می‌شود؛ Vercel در workflowهای این پروژه استفاده نمی‌شود.

- با push به شاخهٔ `main`، GitHub Actions ابتدا `scripts/build_static.py` را اجرا می‌کند.
- فایل‌های runtime موتور Vosk و مدل فارسی در مرحلهٔ ساخت به خروجی اضافه می‌شوند.
- سورس Vosk نسخهٔ 0.0.8 از یک commit پین‌شده دریافت و با Rollup به Worker خارجی هم‌مبدأ تبدیل می‌شود.
- فایل‌های Tesseract و داده‌های زبان فارسی/انگلیسی نیز بررسی می‌شوند.
- فقط پوشهٔ ساخته‌شدهٔ `dist` به GitHub Pages تحویل داده می‌شود.
- شاخهٔ توسعهٔ `chatgpt-push-test-2026-11-13` صرفاً برای توسعه و آزمون است و انتشار خودکار انجام نمی‌دهد.

در تنظیمات مخزن، منبع GitHub Pages را روی **GitHub Actions** قرار دهید.

## قابلیت‌های آفلاین

- ذخیره‌سازی اصلی با IndexedDB و مسیر سازگاری localStorage
- پشتیبان‌گیری و بازیابی فایل‌محور برای انتقال بین دستگاه‌ها
- OCR محلی Tesseract.js با زبان فارسی و انگلیسی؛ تأیید انسانی پیش از ثبت خرید
- تشخیص گفتار فارسی با Vosk/WASM؛ Worker از همان دامنه بارگیری می‌شود و مدل پس از دریافت اولیه cache می‌شود
- دستیار فارسی محلی؛ عملیات مالی و نوشتنی باید از مسیر پیش‌نویس و تأیید عبور کنند
- خرید، فروش، پرداخت چندروش، حسابداری دوبل، صندوق، چک، برگشت و ابطال
- مدیریت تنوع کالا، رنگ، سایز، بارکد، SKU و چند انبار

## امنیت و وابستگی‌های ساخت

- CSP صفحهٔ اصلی فاقد `unsafe-eval` است؛ Worker گفتار به‌صورت فایل خارجی و هم‌مبدأ بارگیری می‌شود.
- اتصال runtime به API ابری یا سرویس تشخیص گفتار ابری تعریف نشده است.
- GitHub Actions در زمان ساخت به Python، Node/npm و دسترسی دریافت سورس/وابستگی‌های پین‌شده نیاز دارد؛ اجرای برنامهٔ ساخته‌شده همچنان ایستا است.
- مدل گفتار برای اولین بار باید روی دستگاه دریافت و cache شود؛ پس از آن پردازش گفتار محلی است.

## آزمون‌ها

- گردش کار `Unique Pro CI` با هر push به شاخهٔ توسعه و هر Pull Request به `main` اجرا می‌شود؛ این گردش کار هیچ انتشار یا Deploy انجام نمی‌دهد.
- آزمون‌ها روی خروجی واقعی `dist` اجرا می‌شوند، نه فقط سورس ریشهٔ مخزن.
- مجموعهٔ فعلی شامل **۳۷ سناریوی مرورگر و پذیرش فروشگاه** است. نتیجهٔ موفق/ناموفق و تعداد assertionهای هر اجرا را از زبانهٔ **Actions** مشاهده کنید؛ تا پیش از اجرای سبز CI، نتیجهٔ موفقی ادعا نمی‌شود.

پیش‌نیازهای اجرای آزمون:

```bash
python -m pip install playwright opencv-python-headless
python -m playwright install chromium
```

در یک ترمینال، سرور ایستا را از ریشهٔ مخزن اجرا کنید:

```bash
python3 -m http.server 8765
```

در ترمینال دیگر:

```bash
python tests/run_tests.py
```

## ساختار اصلی

- `index.html`: رابط اصلی و منطق فعلی برنامه
- `src/engine/`: هستهٔ تراکنش، موجودی و حسابداری
- `src/ui/`: دستیار محلی، NLU، OCR/صوت و ارتقای رابط
- `service-worker.js`: کش آفلاین و به‌روزرسانی برنامه
- `vendor/tesseract/`: موتور OCR و داده‌های زبان محلی
- `scripts/build_static.py`: ساخت خروجی ایستا و آماده‌سازی Vosk
- `tests/`: آزمون‌های رگرسیون مرورگر

## اصول داده

- داده‌های فروشگاه روی دستگاه نگهداری می‌شوند؛ برای جابه‌جایی از پشتیبان/بستهٔ انتقال استفاده کنید.
- خروجی OCR فقط پیش‌نویس است و تا زمان تأیید کاربر نباید خرید یا موجودی ثبت کند.
